RIGHT HALF — CLINICAL WORKFLOW
==============================

Title for this half: "Clinical Workflow — FIB-4 Risk Stratification (age-adjusted)".

The workflow starts at the top with: "Patient opens in clinician dashboard". Draw a single starting node, then split into three vertical swim-lanes labeled "Flow A · Patient has labs", "Flow B · Patient missing labs", and "Flow C · Risk-level follow-up actions". The dashboard widget decides which lane to render at a glance.

------------------------------
Flow A — Patient HAS labs (AST + ALT + Platelets present within 12 months)
------------------------------

Sequence of boxes top-to-bottom, with arrows:

1. "GET /ws/rest/v1/obs?patient=<uuid>"  →  AST, ALT, Platelets fetched.
2. "Calculate FIB-4 = (age × AST) / (Platelets × √ALT)".
3. "Apply age-adjusted thresholds (AGA Clinical Care Pathway / AASLD / McPherson 2017)":
       • Age < 65 → low cutoff = 1.3, upper = 2.67
       • Age ≥ 65 → low cutoff = 2.0, upper = 2.67  (highlight this — it's the age-adjusted rule)
4. "Render risk badge in the widget": a tri-color bar with a needle (green LOW < lower, amber INTERMEDIATE lower–2.67, red HIGH > 2.67).
5. Arrow forks to "Flow C — risk-level follow-up actions".

------------------------------
Flow B — Patient MISSING labs
------------------------------

1. "GET /ws/rest/v1/obs" returns missing AST/ALT/Platelets.
2. Widget shows: "Missing Labs — AST, ALT, Platelet Count" + button "⊕ Order Missing Labs".
3. On click: chain "GET /session → GET /provider?user=… → GET /visit?patient=… (create if absent) → POST /encounter" with order objects:
       • CBC (Complete Blood Count) — covers Platelets
       • Hepatic Function Panel — covers AST + ALT
4. Encounter with type "Visit Note" is posted with the orders. Widget updates to "✓ Orders placed — awaiting results".
5. Arrow loops back to Flow A on next encounter (when labs come back).

------------------------------
Flow C — Risk-level follow-up actions (NEW)
------------------------------

This swim-lane is the new behavior added to the widget. Draw three side-by-side branches based on FIB-4 risk category:

🟢 LOW (FIB-4 < 1.3, or < 2.0 if age ≥ 65)
    → "Continue standard care · rescreen in 2–3 years". No action needed.

🟡 INTERMEDIATE (FIB-4 1.3–2.67, or 2.0–2.67 if age ≥ 65)
    → Widget renders TWO real "Place Order" action rows:
         • FibroScan (VCTE) — LOINC 79961-7
         • Enhanced Liver Fibrosis (ELF) — LOINC 95942-6
    → Click any row: same encounter-POST flow as Flow B (session → provider → visit → POST /encounter with a single test order for that concept).
    → After click, row updates to "✓ Ordered — awaiting result". If an active order already exists, the row instead shows "Already ordered — Awaiting result" without the button.

🔴 HIGH (FIB-4 > 2.67, all ages)
    → Widget renders ONE real "Place Order" action row:
         • Gastroenterology / Hepatology consult (Misc Order class).
    → Same POST /encounter mechanism. Row state cycles: idle → "Place Order" → "Ordered" or "Already ordered — Awaiting result".

------------------------------
Cross-flow callouts (place as small labeled badges on the diagram)
------------------------------

- "Order POST contract": for every order, include the Test Order order_type, Outpatient careSetting, Visit Note encounterType, current visit (created if none active), and current provider (resolved from /session → /provider?user=).
- "Idempotency": each "Place Order" row first calls GET /order?patient=…&concept=… and, if an active order exists, replaces the button with an "Already ordered" badge. Prevents duplicate orders on widget reloads.
